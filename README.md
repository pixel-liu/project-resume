# Project Resume

一个根据项目代码、项目文档和个人贡献说明生成简历项目经历的 Codex skill。

它会先核对项目实际实现，再提炼与目标岗位相关的技术亮点，输出可直接放入简历的项目描述、事实证据和待补充信息。它也可以根据招聘描述调整重点，或围绕最终简历内容生成面试追问。

## 主要能力

- 分析本地仓库、可访问的远程仓库或项目材料，梳理业务场景、技术栈与核心流程。
- 区分项目已有功能、用户个人贡献和基于开源项目的二次开发内容。
- 从架构、缓存、并发、事务、可靠性、工程质量等方面筛选有代码依据的亮点。
- 根据岗位描述调整项目选择、条目顺序和表述重点。
- 生成中文或英文项目经历，并按需提供面试追问与回答提纲。
- 将简历正文、项目证据和待补充信息分开，方便检查与继续完善。

## 写作原则

这个 skill 不会把依赖文件中的技术直接写成已落地能力，也不会根据仓库存在的全部功能推断用户全部负责。对于性能、用户量、QPS、成本、营收或提升比例等数据，只有材料或用户说明能够支持时才会写入。

它会分别判断：

| 维度 | 关注内容 |
|---|---|
| 实现状态 | 功能是否沿实际调用链完成，而非只存在于文档、依赖或接口声明中 |
| 验证状态 | 是否有本次测试、已有测试结果或用户提供的数据支撑 |
| 个人归属 | 用户是否确认负责，或当前材料是否仍需补充说明 |

## 安装

在 Codex 中使用内置的 skill 安装能力：

```text
使用 $skill-installer 从 https://github.com/pixel-liu/project-resume 安装 project-resume skill。
```

也可以手动克隆到默认的个人 skills 目录。在 Windows PowerShell 中运行：

```powershell
git clone https://github.com/pixel-liu/project-resume.git "$env:USERPROFILE\.codex\skills\project-resume"
```

如果已经存在同名目录，请先确认其中是否有需要保留的修改，不要直接覆盖。

## 使用示例

在项目目录中直接调用：

```text
$project-resume 根据当前项目生成一份面向 Java 后端岗位的简历项目经历。
```

结合招聘描述进行适配：

```text
$project-resume 分析当前仓库，并根据下面的招聘描述筛选最相关的项目亮点：

<粘贴招聘描述>
```

补充个人贡献边界：

```text
$project-resume 这是一个团队项目。我负责订单、库存和消息消费模块，请根据当前代码生成简历项目经历。
```

检查已有描述是否准确：

```text
$project-resume 核对下面的项目经历是否能被当前代码支持，并给出更准确的版本：

<粘贴已有项目经历>
```

准备面试追问：

```text
$project-resume 根据最终项目经历生成面试追问和回答提纲，重点检查并发、事务和异常处理。
```

## 默认输出

通常会包含三部分：

1. 可直接粘贴到简历中的项目简介、技术栈和约 3–5 条项目经历。
2. 支撑每条候选亮点的实现状态、验证状态、个人归属和代码位置。
3. 会影响当前成稿的待补充信息，例如个人负责范围、项目时间或指标口径。

没有招聘描述时，skill 会先生成通用技术版；只有项目材料时，会先完成项目经历部分，不会编造教育背景、工作经历或其他个人信息。

## 仓库结构

```text
project-resume/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── references/
    ├── evidence-and-writing.md
    ├── interview.md
    └── role-targeting.md
```

- `SKILL.md`：skill 的入口、工作流程和真实性约束。
- `references/evidence-and-writing.md`：证据状态、指标口径和简历表达规范。
- `references/role-targeting.md`：岗位适配与多项目筛选方法。
- `references/interview.md`：围绕最终简历内容生成面试追问的规范。
- `agents/openai.yaml`：Codex 界面展示信息。

## 适用边界

该 skill 适合从真实项目材料生成或核查简历项目经历。脱离项目材料的通用简历润色、求职信撰写，以及没有依据的经历包装不属于它的主要范围。
